# Contributing

## Everyday workflow

Start from an up-to-date `main` branch:

```powershell
git switch main
git pull --ff-only
git switch -c feature/short-description
```

Make a focused change, then validate it locally:

```powershell
npm test
git status
git diff
git add path/to/changed-files
git commit -m "Describe the change"
git push -u origin feature/short-description
```

Open a pull request from the feature branch into `main`. Explain what changed,
why it changed, and which checks passed. After review and passing checks, merge
the pull request on GitHub, then clean up locally:

```powershell
git switch main
git pull --ff-only
git branch -d feature/short-description
git push origin --delete feature/short-description
```

## Commit guidance

- Keep commits focused and easy to explain.
- Do not commit `dist/`; it is generated by the build.
- Run `npm test` before opening a pull request.
- Use imperative commit messages such as `Add product comparison page`.
